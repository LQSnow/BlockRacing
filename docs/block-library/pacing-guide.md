# 阶段难度与探索节奏

比赛按本队完成目标的进度，从基础发育逐步加入探索、加工和高难挑战。规则只读取进度、预设和候选数据，不根据装备、队伍领先情况或当前四个槽位临时调权。

## 等级阶段

|已完成进度|50 目标时的起点|可新出现的等级|
|---|---:|---|
|0%|0 个|T1–T2|
|15%|8 个|T1–T3|
|35%|18 个|T1–T4|
|60%|30 个|T1–T5|
|80%|40 个|T1–T6|

阈值使用 `ceil(total * percent / 100)`，与队伍积分、现实时间或已生成序号无关。阶段范围还要与所选预设及维度门槛取交集：标准不会出现 T5/T6，困难不会出现 T6，噩梦也不会在开局出现高等级目标。

开局四个目标按完成数 0 抽取。每次完成、补位和重抽都使用当下已完成数；已有目标不会因为跨阶段而自动替换。

## 等级权重

实际等级权重等于预设的基础权重乘以当前阶段倍率。0 表示尚未开放；正数是倍率，不是任务数量或百分比。

|阶段开始进度|T1|T2|T3|T4|T5|T6|
|---|---:|---:|---:|---:|---:|---:|
|0%|8|3|0|0|0|0|
|15%|4|4|1|0|0|0|
|35%|2|3|4|1|0|0|
|60%|1|2|4|3|1|0|
|80%|1|1|2|4|4|2|

高等级刚开放时权重较低，随后逐步提高。较低等级保留抽取机会，后期也不会强制全部使用高难目标。不存在固定简单槽或按槽位组合补任务的规则。

## 获取方式

目标分为常规采集 GATHER、加工制作 CRAFT 和探索获取 EXPLORE，按主要获取途径归类。加工标签不等于简单，高成本制作仍须等待其等级开放。

|已完成进度|采集|加工|探索|
|---|---:|---:|---:|
|0%～不足 20%|45|40|15|
|20%～不足 80%|25|30|45|
|80% 起|30|40|30|

抽取顺序为：合法维度、合法等级及动态权重、该层获取标签、具体方块。标签为空时仅在当前合法层内重新分配权重，不从未开放维度或等级借用目标。

## 配置与兼容

五份 `presets/*.yml` 的 `tier-progression` 配置等级阶段，`pacing` 配置获取方式权重，二者独立。

`tier-progression.stages` 每项包含 `start-percent` 和六项 `tier-multipliers`。阶段须从 0% 开始并严格递增，已开放等级不可在后续重新锁定，最后阶段倍率均为正。是否允许某个等级仍由预设或自定义选择决定。

分级自定义沿用等级阶段，必须保留足够开局候选；只选高等级而没有初始可用目标时会拒绝开局。本地文件的 `tier-progression` 独立配置，默认关闭，不继承界面设置。

旧磁盘预设缺少等级阶段时会补入默认规则。已开始的比赛继续使用存档中的候选、门槛和随机序列，不因更新或修改配置而改变目标；新规则从下一局生效。存档规则损坏时会拒绝恢复并保留原文件。
